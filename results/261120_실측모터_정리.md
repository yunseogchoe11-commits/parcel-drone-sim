# 11/20 시뮬 업데이트: 가정 모터(AIR2216 II) + 2,600 g + 아래쪽 카메라·AprilTag (김수민)

> 11/21 수정: 실제 모터를 아직 모름. 키트 모터(2216 KV920 + 10인치)를 같은 급인 T-Motor AIR2216 II 공식 추력표로 **가정**한 값임. 아래 "실측"은 "가정 모터"로 읽을 것. 추력 15 % 낮춘 최악 조건 결과는 `261121_2600g_정리.md`

랩실 PC(Ubuntu 24.04, PX4 v1.17.0 SITL, Gazebo Harmonic)에서 돌린 결과. 결과 폴더마다 `flight.ulg`(비행 로그), `params.txt`(비행 당시 PX4 파라미터 전체), `params_changed.txt`(PX4 기본값과 다른 것만)를 붙임.

## 1. 바꾼 것

### 모터 (models/x500_mydrone/model.sdf)
원래 모델은 PX4 기본 x500 모터 상수(특정 모터 추력표 기준 아님)였음 → 키트 모터를 AIR2216 II 공식 추력표로 가정해서 맞춤 (실제 모터 확인·추력 실측 필요).

| 항목 | 기존 (PX4 기본 x500) | 변경 (가정: AIR2216 II KV920 + T1045 II, 14.8 V) |
|---|---|---|
| motorConstant (T = k·ω²) | 8.54858e-6 | 1.22990e-5 |
| maxRotVelocity | 1000 rad/s | 954.8 rad/s (= 9,118 rpm) |
| momentConstant | 0.016 | 0.0140 |
| 모터당 최대 추력 | 872 g | 1,143 g |
| 4개 합계 | 3.49 kgf | 4.57 kgf |

- 근거: T-Motor 공식 추력표 (store.tmotor.com, AIR2216II-KV920 + T1045, 16 V, 스로틀 30~100 % 15점). 100 %: 1,332 g, 9,857 rpm
- k: 15점에 T = k·ω² 최소제곱. 14.8 V 최대 회전 = 9,857 × 14.8/16 rpm
- momentConstant: 추력표 토크 ÷ 추력
- 모델 하나로 바꾸는 명령: `python3 tools/vehicle/set_mass_cg.py 2600 -14 --motor air2216` (`--motor px4`면 원래 모터)

## 2. 호버링 (1.5 m, 약 24 s 정지 구간, `scripts/hover_test.py` + `tools/analysis/analyze_hover.py`)

| 결과 폴더 (results/) | 무게 | 무게중심 | 모터 | 호버 스로틀 | 모터 출력 앞/뒤 | 자세 최대 | 수평 흔들림 최대 |
|---|---|---|---|---|---|---|---|
| 261120_hover_2400g_cg-17.7 | 2,400 g | −17.7 mm | PX4 기본 | 69.4 % | 0.631 / 0.757 | 0.05° | 3.1 cm |
| 261120_hover_2400g_cg-14 | 2,400 g | −14 mm | PX4 기본 | 69.4 % | 0.645 / 0.742 | 0.07° | 1.5 cm |
| 261120_hover_2600g_cg-14_px4motor | 2,600 g | −14 mm | PX4 기본 | 75.3 % | 0.700 / 0.806 | 0.08° | 1.4 cm |
| **261120_hover_2600g_cg-14_air2216** | 2,600 g | −14 mm | **가정 (AIR2216 II)** | **56.7 %** | 0.527 / 0.608 | 0.05° | 2.8 cm |

- 호버 스로틀 = 무게 ÷ 최대 추력 합계. 계산값 74.6 % / 56.9 %와 시뮬 결과가 맞음 → 모터 모델 정상 반영
- 같은 2,600 g에서 모터만 바꿔 75.3 % → 56.7 %. 발표 때 손계산(55~59 %)과 같은 범위
- 모터 출력(actuator_motors)은 추력 비율 명령. THR_MDL_FAC 곡선으로 Gazebo 회전수로 바꿔 역산하면 앞·뒤 추력이 힘·모멘트 균형 손계산과 2 % 안에서 일치

## 4. 아래쪽 카메라 + AprilTag 정밀 접근 (틀만, results/261120_tag_approach)
- 카메라: 모듈 미정이라 IMX219 + 라즈베리파이 v2 렌즈 가정 (가로 62.2°, 640×480, 15 Hz), 기체 중심 앞 0.12 m·아래 0.03 m, 바로 아래 (`tools/vehicle/set_camera.py`, 토픽 /down_camera/image)
- 태그: tag36h11 id 0, 검은 사각형 0.144 m, P 택배 상자 윗면 (`tools/world/add_apriltag.py` — 월드에 이 PC의 절대 경로가 들어가서 worlds/auditorium.sdf는 안 올림. 각자 PC에서 스크립트 실행)
- 방법 (`scripts/tag_approach_test.py`): 광류로 P 이동 → 인식 → 북·동 25 cm 이동으로 카메라→북·동 행렬 측정 → 태그 위로 반복 맞춤 (1.5 m → 1.0 m)
- 결과: 광류만으로 P 도착 시 태그까지 37.4 cm → 1.0 m에서 최종 2.3 cm. 측정 행렬 [[−1.00 −0.04] [0.00 −0.93]]
- 확인할 점: 카메라로 잰 태그 거리가 예상보다 20~25 cm 김 (거리계가 상자 윗면을 재서 실제로 더 높이 떴을 가능성) → 로그의 실제 고도로 확인 예정
- 필요한 것: 카메라 모듈 정확한 모델명·장착 위치·각도, 카메라-그리퍼 거리

## 5. 다시 돌리는 법
```bash
cd ~/parcel-drone-sim
python3 tools/vehicle/set_mass_cg.py 2600 -14 --motor air2216   # 무게·무게중심·모터 + run_mydrone_flow_test.sh
python3 tools/vehicle/set_camera.py                              # (4번) 카메라
python3 tools/world/add_apriltag.py                              # (4번) 태그
bash tools/run_mydrone_flow_test.sh                              # 터미널 ① SIM
python3 scripts/hover_test.py        # 또는 mission_hdph.py / tag_approach_test.py 폴더이름   (터미널 ③)
python3 tools/analysis/analyze_hover.py 폴더이름                  # 분석
python3 tools/analysis/attach_log.py results/폴더이름              # 로그·파라미터 붙이기
```
필요 패키지: pyulog, matplotlib, "mavsdk<4", pupil-apriltags, opencv-python, python3-gz-transport13, python3-gz-msgs10
